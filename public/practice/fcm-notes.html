02 / PRACTICE LOG

What each step proved

Capability gate

FCM should not initialize blindly. isSupported() checks whether the browser environment provides the APIs Firebase Messaging needs. On iPhone, Web Push belongs to an installed Home Screen web app, not an ordinary browser tab.

Permission

Notification.requestPermission() must follow a deliberate user gesture such as pressing CONNECT. A server cannot grant permission and code should not try to ambush the user with the prompt.

Service-worker registration

The page registers /firebase-messaging-sw.js. Because it lives at the site root, its default scope covers the whole site. The worker can continue receiving background events when the page is hidden or closed.

Registration token

getToken() combines the Firebase project, browser push subscription, service worker, and public VAPID key into an addressable FCM registration token. It is an installation address, not a human identity and not a permanent username.

Foreground delivery

When the page is visible, onMessage() receives the payload in page JavaScript. The receiver can update immediately without making the user tap a system notification.

Background delivery

When the PWA is closed or backgrounded, messaging.onBackgroundMessage() runs in the service worker. For our data-only messages, the worker calls showNotification() itself.

03 / THE USEFUL WRONG TURN

Why Firebase Console opened the index

A Firebase Console test notification contains a notification payload. Firebase/browser machinery automatically displays it. On iPhone, tapping that automatically generated notification opened the installed PWA's start location—the site index.

Adding a custom notificationclick listener did not give us reliable ownership of that automatically displayed notification. This was not a broken PWA; it showed that display ownership matters.

The correction

We stopped using the Console as the real sender. A local Node script sends a data-only payload. Data-only means Firebase delivers information silently to the worker; our worker decides the title, body, icon, stored destination, and click behavior. 

data: {
  title: "BAUDOT",
  body: "HELLO ESTEBAN",
  signal: "HELLO ESTEBAN"
}
04 / SENDER

Why the Node script is trusted

The browser uses public project configuration and a public VAPID key. Those identify the Firebase project but do not grant administrative sending power.

send-fcm.mjs runs locally and loads a service-account private key through Firebase Admin. That credential authorizes it to ask FCM to send messages for the skilseting project. 

$token = (Get-Clipboard).Trim()
node .\send-fcm.mjs $token "HELLO ESTEBAN"

The first attempt passed the literal placeholder PASTE_TOKEN_HERE. Firebase returned INVALID_ARGUMENT. That harmless error proved Node, Firebase Admin, the service-account key, and the project authentication were already functioning.

05 / SECURITY BOUNDARIES

Public things and private things

May live in browser code

  • Firebase web configuration
  • Project ID and messaging sender ID
  • Public VAPID key

Must remain private

  • private/serviceAccountKey.json
  • Any server credential or private key

GitHub Desktop confirmed that only .gitignore, package files, and send-fcm.mjs were eligible to commit. The private directory, key, and dependencies were absent from Changes.

Registration tokens

A registration token is a delivery address. It is not equivalent to the service-account key, but it should not be casually published: someone with both a valid token and authorized sending infrastructure could target that installation. Tokens can also rotate or become invalid.

06 / VOCABULARY

Words worth owning

  • PWA: an installable web application.
  • FCM: Firebase Cloud Messaging, the delivery service.
  • Service worker: background JavaScript associated with an origin and scope.
  • VAPID key: public application-server identity used for Web Push subscription.
  • Registration token: an FCM address for one app installation.
  • Notification payload: display-oriented content that Firebase may show automatically.
  • Data-only payload: string key/value data handled by application code.
  • Firebase Admin SDK: trusted server-side access authenticated by a service account.
  • Foreground: the page is visible and can handle onMessage().
  • Background: the service worker handles delivery while the page is not active.
07 / NEXT-SESSION QUIZ PREP

Questions to sleep on

  1. Why does iPhone Web Push require the page to be installed?
  2. What does an FCM registration token identify?
  3. Why is the VAPID public key safe in browser code?
  4. Why must the service-account JSON never enter public/?
  5. Which code handles a message while the receiver page is visible?
  6. Which code handles it while the PWA is closed?
  7. Why did the Firebase Console notification open the site index?
  8. What changed when we sent a data-only message?
Compact answers
  1. iOS exposes Web Push to installed Home Screen web apps.
  2. One Firebase Messaging app installation, not necessarily one person.
  3. It is deliberately public identity material, not an administrative credential.
  4. Hosting would expose a master credential to every visitor.
  5. The page's onMessage() listener.
  6. The service worker's onBackgroundMessage() listener.
  7. The automatically displayed notification used the PWA's default start location.
  8. Our worker gained control over display, stored data, and tap routing.
08 / WHERE WE GO NEXT

Address books, not pasted tokens

The natural next layer is a small registry that associates a friendly name—such as iphone-esteban or android-test—with the latest registration token. The sender can then address a name instead of receiving a giant token on every command.

That introduces the next serious subjects: authentication, permission to register or replace a token, token rotation, groups, message history, and deciding whether a sender is local, server-hosted, or part of a protected control page.
